# 지도 편집기 사용성 개선 (Undo/Redo · 드래그 이동 · 라벨 충돌 감지 · 저장 상태 UX)

이 문서는 `app/jipseul-note.html`의 지도(Map) 편집 기능에 추가된 대규모 업데이트를 정리한 것입니다. 기존 기능(지역 그리기, 마커/게이트/위험구역 배치, 세력권 보기, 회차 시스템, 빈틈 채우기 등)은 전부 그대로 유지한 채 리팩토링했습니다.

## 0. 배경 및 범위 결정

요청에는 "Canvas 또는 WebGL 활용 검토"가 포함되어 있었지만, 이 앱은 빌드 도구 없는 단일 HTML 파일로 동작하는 구조이기 때문에 렌더링 엔진을 SVG에서 WebGL로 바꾸는 것은 사실상 전체 지도 시스템을 새로 설계하는 수준의 작업입니다. 사용자와 상의한 결과 **SVG를 유지하고 성능은 맞춤 최적화로 해결**하기로 했습니다(아래 6장 참고). 또한 드래그 이동은 1차로 **점 객체(마커·위험구역·게이트)에만** 적용하고, 지역(다각형) 전체 드래그는 범위에서 제외했습니다(손으로 그린 불규칙한 다각형이라 전체 이동 시 "공백 금지 규칙"과의 충돌 여지가 더 크기 때문 — 필요해지면 다음 단계에서 추가 가능).

## 1. Undo/Redo — state-history 구조

### 1-1. 왜 "단순 DOM 복원"이 아니라 상태 기반인가
지도 데이터는 이미 `mp.regions / mp.lines / mp.markers / mp.dangerZones / mp.gates` 라는 명확한 배열 구조를 갖고 있고, 회차(버전) 복제 기능(`addMapVersion`)이 이미 `JSON.parse(JSON.stringify(...))` 방식의 깊은 복사를 쓰고 있었습니다. 이 패턴을 그대로 재사용해 **매 편집 지점마다 개별적으로 "지금부터 편집합니다" 신호를 넣는 대신**, 편집이 끝나면 예외 없이 전체 재렌더 함수 `drawMap(mp)`가 호출된다는 사실을 이용했습니다.

```
history = { past: [snapshot0, snapshot1, ...], future: [] }
```

- `drawMap(mp)`가 호출될 때마다 함수 맨 끝에서 `mapHistoryCommit(mp)`를 부릅니다.
- 현재 상태의 스냅샷(JSON 문자열)을 만들어 `past` 스택의 마지막 항목과 비교합니다.
- **내용이 같으면 아무것도 쌓지 않습니다.** 선택 변경, 세력권 보기 토글처럼 데이터는 안 바뀌고 화면만 다시 그리는 경우가 여기 해당합니다.
- **내용이 다르면** 새 스냅샷을 `past`에 쌓고 `future`(redo 스택)는 비웁니다(표준 undo/redo 관례 — 새 편집이 생기면 이전에 되돌렸던 redo 이력은 무효).

이 설계 덕분에 **지역 생성/삭제/이름변경, 마커/게이트/위험구역 생성/삭제/이동, 선 연결/삭제, 지도 페인팅(지역 그리기), 세력 연결 변경, 빈틈 채우기** 등 요청에 나열된 모든 편집 동작이 **기존 코드를 건드리지 않고도** 자동으로 undo/redo 대상이 됩니다. 새 편집 함수를 추가할 때도 `drawMap(mp)`만 마지막에 부르면 히스토리에 자동으로 잡힙니다.

### 1-2. Undo/Redo 실행
```js
function mapUndo(mp) {
  var cur = mapHistory.past.pop();
  mapHistory.future.push(cur);
  mapApplySnapshot(mp, mapHistory.past[mapHistory.past.length-1]);
}
```
`mapApplySnapshot`은 스냅샷을 `mp.regions/lines/markers/dangerZones/gates`에 그대로 되돌리고 `saveData()` + `drawMap(mp)`를 호출합니다.

### 1-3. UI
- 지도 툴바에 "실행 취소" / "다시 실행" 버튼(되돌릴 것이 없으면 자동으로 비활성화).
- 단축키: `Ctrl+Z`(Mac `Cmd+Z`) / `Ctrl+Shift+Z`(Mac `Cmd+Shift+Z`). 입력 필드에 포커스가 있을 때는 동작하지 않도록 가드 처리.
- 최대 60단계까지 보관(그 이상은 가장 오래된 기록부터 버림 — 메모리 상한).
- 히스토리는 지도별로 독립적이며(`mapHistory.mapId`로 구분), 세션 메모리에만 있고 `localStorage`에는 저장하지 않습니다(새로고침하면 초기화 — 데이터 자체는 이미 저장되어 있으므로 안전합니다).

## 2. 점 객체 드래그 이동

마커·게이트·위험구역은 기존에 **클릭 한 번 = 선택 + 편집 모달 열기**로 동작했습니다. 이를 마우스 다운/이동/업 세 단계로 분리해서 "클릭"과 "드래그"를 구분합니다.

- `mousedown`: `mpState.dragObj = { type, id, obj, el, startX, startY, startMouseX, startMouseY, moved:false }`만 기록하고 아무것도 하지 않음(기존 관계도 편집기의 `gState.dragNode` 패턴을 그대로 재사용).
- `mousemove`(창 전역): 마우스 이동량을 뷰 배율(`mp.view.scale`)로 나눠 월드 좌표 델타를 구하고, 해당 객체의 `x/y`만 갱신 + **그 요소의 `transform` 속성만 직접 갱신**(전체 재렌더 없음 — 기존 팬 이동과 동일한 최적화 패턴). 3px 이상 움직이면 그때부터 `moved=true`로 표시하고 `.dragging` 클래스(커서를 `grabbing`으로) + 살짝 확대 효과를 줌.
- `mouseup`: 실제로 움직였으면(`moved`) 좌표를 확정 저장(`saveData(); drawMap(mp)`, 즉 1-1의 undo 스냅샷도 자동으로 잡힘). **움직이지 않았으면** 이전과 동일하게 선택 + 편집 모달을 엽니다 — 드래그 기능 도입 전 클릭 동작을 완전히 보존.

## 3. 선택 시각 피드백

- 선택된 요소(지역/선/마커/게이트/위험구역) 전체에 공통으로 글로우 효과(`filter: drop-shadow(...)`, accent 색상 2겹).
- 마커/게이트/위험구역은 선택되거나 드래그 중일 때 `transform` 속성 문자열에 `scale(1.08)`을 직접 덧붙여 8% 확대합니다. (SVG는 `transform` **속성**과 CSS `transform` **프로퍼티**가 같이 있으면 CSS 쪽이 속성을 완전히 덮어써서 위치가 원점으로 틀어지는 함정이 있어, 확대는 CSS가 아니라 속성 문자열 자체에 넣었습니다.)
- 커서: 평소 `grab`, 드래그 중에는 `grabbing`.

## 4. 라벨 충돌 감지 + 자동 보정

완전한 force-directed 레이아웃 엔진 대신, **그리디 방식의 Smart Label Placement 단순화 버전**을 구현했습니다(`layoutMapLabels`).

1. 지역명, 문파(세력)명, 마커/게이트/위험구역/선 이름 등 화면에 그려질 모든 라벨을 `{key, x, y, text, fontSize}` 형태로 한 번에 모읍니다.
2. 각 라벨의 예상 폭을 글자 단위로 추정합니다(`mapLabelEstWidth` — 한글/한자 등 전각 문자는 `fontSize*0.98`, 영문/숫자 등 반각은 `fontSize*0.56`으로 근사 — SVG는 캔버스 `measureText` 없이는 실제 텍스트 폭을 알 수 없어 쓴 근사치입니다).
3. 그려지는 순서대로, 이미 배치된 라벨들의 사각형과 겹치면 위/아래로 점점 더 크게(1칸, 1칸, 2칸, 2칸 …) 밀어내며 겹치지 않는 위치를 찾습니다(최대 10회 시도).
4. 계산된 세로 오프셋(`dy`)을 각 `<text>`의 y좌표에 더해서 그립니다.

수백 개 라벨이 있어도(현실 세계 177개국 템플릿 기준 실측 181개 지역 포함 전체 재렌더 381ms) 이 비교는 `O(n²)`이지만 전체 재렌더가 편집이 끝난 시점에만 한 번 일어나는 구조라 체감 지연이 없습니다.

**줌 수준에 따른 표시**: `mp.view.scale`에 따라 `#mapG`에 `data-zoom="low|mid|high"`를 매기고(임계값 0.55 / 1.6), 많이 축소했을 때(`low`)는 부차적인 라벨(마커·게이트·위험구역·선 이름, 문파명, 게이트 등급 표시)을 옅게 줄여 핵심 지역명만 도드라지게 했습니다.

**가독성**: 기존에 이미 모든 라벨에 `paint-order:stroke; stroke:var(--bg-card); stroke-width:3px` 방식의 외곽선(halo)이 적용되어 있었습니다 — 이번 작업으로 새로 추가한 것이 아니라 기존 구현을 그대로 활용했습니다.

## 5. 저장 상태 UX

지도 편집은 `saveData()`가 편집 하나가 끝날 때마다 **동기적으로** `localStorage`에 기록하므로, 사실상 항상 자동 저장 상태입니다. 서버 왕복이 있는 앱과 달리 "임시 초안 vs 저장된 상태"의 구분이 원래 없다는 점을 감안해, **정직하게 실제로 저장 전인 구간만** 표시합니다.

- 유일한 진짜 "미저장" 구간은 **드래그 도중**(마우스를 누른 채 이동 중, 아직 `mouseup` 전)입니다. 이때만 `● 저장 안 됨`을 표시합니다.
- 그 외에는 `✓ 저장됨 · 오후 3:42:07`처럼 마지막으로 데이터가 바뀐 시각을 표시합니다(1장의 `mapHistoryCommit` dedup 로직을 그대로 재사용 — 실제로 데이터가 바뀐 순간에만 시각을 갱신).
- **이탈 경고**: 드래그가 진행 중일 때만 `beforeunload`를 막아(브라우저 기본 확인창) 마우스를 뗀 순간까지 페이지를 닫아도 데이터 손실이 없게 했습니다. 페이지를 벗어날 때마다 이전 리스너를 정리하고 새로 등록합니다(팬/드래그 이벤트 정리와 동일한 패턴).

## 6. 성능 관련 결정

| 항목 | 결정 | 근거 |
|---|---|---|
| 렌더링 엔진 | SVG 유지 (Canvas/WebGL 미도입) | 빌드 도구 없는 단일 파일 구조에서 WebGL 전환은 렌더링 엔진 전체 재설계 수준. 실측상 177개국 + 자동 채움 4곳(총 181개 지역) 전체 재렌더가 381ms로 여유 있음 |
| 드래그 중 갱신 | 전체 재렌더(`drawMap`) 대신 해당 요소의 `transform` 속성만 직접 갱신, `mouseup`에서만 전체 재렌더 | 기존 팬(지도 이동) 최적화와 동일한 패턴 재사용 |
| 라벨 충돌 검사 | `O(n²)` 그리디 비교, 스냅샷/재렌더 시점에만 1회 실행 | 수백 개 라벨 규모에서도 실측 밀리초 단위 — 매 프레임 계산이 아니므로 별도 공간 인덱싱(쿼드트리 등) 불필요 |
| Undo 히스토리 메모리 | 지도별 최대 60단계 보관 후 오래된 기록부터 폐기 | 대규모 세계관에서도 메모리 상한을 둠 |

## 9. 추가 업데이트 — 이미지 회전 UI 리메이크 (각도 슬라이더 → 드래그 핸들)

배경 이미지 회전(2장의 크롭·회전 도구 중 "회전")이 기존에는 `<input type="range">` 각도 슬라이더 + 숫자였는데, 이를 **포토샵/그림판/피그마 스타일의 드래그 핸들 회전**으로 리메이크했습니다. 슬라이더는 완전히 제거하고, 정밀 입력이 필요한 소수 사용자를 위해 작은 숫자 입력 필드를 보조 기능으로만 남겼습니다.

### 9-1. 구성 요소

- **회전 핸들**: 회전 중심(피벗) 바로 위 70 world-unit 지점에 뜨는 원형 핸들(`#mapRotateHandle`). 드래그하면 그 방향으로 이미지가 실시간으로 돈다.
- **중심점(피벗) 표시**: 십자 마커(`#mapRotatePivot`, 기본값은 이미지 정중앙). 이 마커도 직접 드래그해서 회전 중심을 옮길 수 있다("중심점 재설정" 버튼으로 다시 정중앙으로).
- **안내선**: 중심점→핸들을 잇는 점선(`#mapRotateGuide`).
- **각도 표시**: 핸들 옆에 실시간 각도 텍스트(`#mapRotateAngleText`), 툴바 좌측에 큰 글씨 각도 표시(`#mapRotateReadout`).
- **빠른 회전 버튼**: −90°/−45°/180°/+45°/+90° 5개, 클릭 즉시 확정 적용(드래그 미리보기 단계를 거치지 않음).
- **보조 정밀 입력**: 작은 숫자 입력 필드(`#mapRotateNumInput`) — 정확한 각도가 필요할 때만 쓰는 보조 수단으로 격하.

### 9-2. 상호작용 흐름

1. 핸들(또는 중심점)에서 `mousedown` — 각 요소 자체에 리스너를 달고 `stopPropagation()`으로 캔버스의 일반 드래그/그리기 처리로 이벤트가 새지 않게 막는다. 회전 도구가 활성화된 상태에서 캔버스의 빈 공간을 클릭해도(핸들이 아니면) 아무 일도 일어나지 않도록 별도 가드도 추가했다 — 예전 슬라이더 UI 시절엔 캔버스 클릭 자체가 아무 의미가 없어서 문제되지 않았던 경로다.
2. `mousemove`(창 전역, 기존 팬/드래그 이동과 같은 핸들러) — 마우스 좌표를 중심점 기준 각도(`atan2`)로 변환해 드래그 시작 각도와의 **차이**만큼 각도를 갱신한다. 절대각이 아니라 델타 방식이라 중심점을 드래그로 옮겨도(=핸들의 절대 위치가 바뀌어도) 회전 각도 계산 자체는 영향받지 않는다.
3. **Shift 스냅**: `e.shiftKey`가 켜져 있으면 `[0,15,30,45,60,90,120,135,180]`(±) 목록에서 가장 가까운 값으로 스냅한다.
4. 갱신은 배경 이미지의 SVG `transform` 속성만 직접 바꾸는 가벼운 미리보기다(`drawMap` 재호출 없음, 기존 마커/게이트 드래그 최적화와 동일한 패턴). 지역·마커 등 콘텐츠 좌표는 "적용"을 눌러야 실제로 재투영된다.
5. "적용"을 누르면 `applyMapRotation(mp, deg, pivot)`이 이미지를 실제로 캔버스에 다시 그려 래스터화하고(임의 피벗 지원하도록 일반화 — 기존엔 이미지 정중앙 고정이었음), 지역/선/마커/**위험구역/게이트**(기존엔 누락되어 있던 버그, 이번에 함께 고침) 좌표를 전부 재투영한다.

### 9-3. Undo/Redo — 발견한 버그와 수정

배경 이미지 관련 필드(`bgImage/bgWidth/bgHeight/bgMode/traceImage`)는 원래 `mapSnapshot`에 **포함되어 있지 않았습니다** — 1장의 Undo/Redo 히스토리는 `regions/lines/markers/dangerZones/gates`만 찍고 있었기 때문에, 회전을 적용해도 실행취소가 배경 이미지 크기·내용을 되돌리지 못하는 버그가 있었습니다(마커 좌표 등은 되돌아가지만 이미지는 회전된 채로 남는 불일치 상태). `mapSnapshot`/`mapApplySnapshot`에 배경 이미지 필드를 추가해 고쳤습니다.

이 과정에서 파생된 문제 하나를 더 고쳤습니다: 회전·자르기 후에는 배경 이미지의 자동 선 감지(트레이스)가 비동기로 다시 돌면서 `drawMap`을 한 번 더 호출하는데, 배경 이미지가 스냅샷에 포함된 뒤로는 이게 **별도의 undo 단계**로 잡혀서 Ctrl+Z 한 번으로는 트레이스 모드만 되돌아가고 실제 회전은 그대로 남는 2단계 undo가 생겼습니다. 이 후속 재렌더만 히스토리에 안 쌓이도록 억제하는 플래그(`mapHistorySuppressed`)를 추가해, "회전 적용"이 사용자 입장에서 한 번의 undo 단위가 되도록 맞췄습니다(크롭 도구도 같은 구조라 함께 적용).
