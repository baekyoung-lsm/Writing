# 무주지 및 신규 국가 생성 정책 (영역 유형·소유권 개편)

이 문서는 `app/jipseul-note.html` 지도 시스템에 추가된 "무주지 및 신규 국가 생성 정책"을 정리합니다. 기존의 "지도 영역 공백 금지 규칙"(빈틈 자동 감지·채우기, `docs/map-editor-upgrade.md` 이전 작업)은 그대로 유지하면서, 그 규칙이 막는 대상을 "의도되지 않은 빈 땅"으로 명확히 좁히고 사용자가 명시적으로 만든 무주지·중립지대·미개척지 등은 정상 영역으로 인정하도록 확장했습니다.

## 0. 기본 원칙

- 금지 대상은 **의도되지 않은 빈 땅**뿐입니다. 국가/도시국가/문파 영토/종교 세력권/부족 영역/마교 영역/길드 영역/중립지대/무법지대/미개척지/공백지대/황무지/던전 구역/이계 침식지/사용자 정의 영역 — 이 15가지는 모두 사용자가 명시적으로 그린 경우 정상 영역으로 인정됩니다.
- "무주지"(소유자 없음, `houseId: null`)는 **사용자가 직접 만들었을 때만** 허용됩니다. 시스템이 자동으로 무주지를 만드는 경우는 없습니다 — 기존 "빈틈 채우기" 기능도 무주지가 아니라 `regionKind: "frontier"`(미개척지) 타입의 실제 영역을 만들어 채우는 방식이라 이 원칙과 충돌하지 않습니다.
- Topology 규칙(국가 중첩 금지, 경계 틈 금지, 찢어진/잘못된 Polygon 금지)은 그대로 유지됩니다. 이번 정책은 "영역이 무엇을 의미하는가"에 대한 데이터 모델·UI 개편이며, 기존 공간적 정합성 로직(빈틈 감지 등)은 손대지 않았습니다.

## 1. 영역 유형(regionKind) 데이터 모델

`region.regionKind`는 지형(`region.terrain`, 산/숲/사막 등 지리적 속성)이나 소속(`region.houseId`, 어떤 세력 문서에 연결됐는지)과는 **완전히 독립적인 축**입니다. 세 값을 자유롭게 조합할 수 있습니다(예: 지형은 "사막", 소속 세력은 없음, 유형은 "무법지대").

```js
var REGION_KINDS = {
  country, cityState, sectTerritory, religiousDomain, tribalTerritory,
  demonicSect, guildTerritory, neutralZone, lawlessZone, frontier,
  voidZone, wasteland, dungeonZone, otherworldRift, custom
}; // 15종, 각 { label, color }
```

기존 지역에는 마이그레이션으로 기본값을 채웁니다: 라벨이 "미개척지"로 시작하면 `frontier`, 그 외엔 `country`. `region.customColor`도 함께 추가되며(`null`이면 지형 기본색 사용, 값이 있으면 그 색이 우선) 지역 편집 모달에 색상 스와치 + "기본색으로" 리셋 버튼으로 노출됩니다.

## 2. 새 영역 생성 흐름

지도 편집기 툴바의 "지역" 도구(페인트)를 선택하면 기존 지형 선택 행 옆에 **영역 유형 선택 행**이 함께 나타납니다(`mapRegionKindRow`, `terrainRowHtml`과 동일한 패턴). 사용자가 유형을 먼저 고르고(`mpState.regionKind`), 지도 위에 다각형을 그리면, 그리기가 끝나는 즉시 이름·유형·색상을 입력하는 생성 모달이 열립니다(`openMapRegionModal(mp, newRegion, true, onDone)` — `isNew=true`일 때는 "새 영역 만들기" 제목과 "생성 완료" 버튼으로 바뀝니다). **모달을 확인하기 전까지는 지역이 `mp.regions`에 들어가지 않습니다** — 위험구역·게이트 생성과 동일한 "그리기 → 즉시 편집 → 확정 시 추가" 패턴입니다.

절차: ① "지역" 도구 클릭 → ② 영역 유형 선택 → ③ 지도에 다각형 그리기 → ④ 이름 입력 → ⑤ 색상 선택(선택사항, 기본은 지형색) → ⑥ 생성 완료.

## 3. 영토 공백화(무주지 전환)

지역 편집 모달에서 소속 세력이 있는 지역에는 "무주지로 전환" 버튼이 나타납니다. 누르면 `houseId = null`, `regionKind = "frontier"`로 즉시 바뀝니다(전쟁 후 폐허, 재앙 발생 지역 등을 한 번에 표현하는 지름길 버튼일 뿐이며, 유형/소속은 각자 독립적으로도 자유롭게 바꿀 수 있습니다).

## 4. 영토 양도

국가 A에서 국가 B로 영토를 옮기는 기능은 **이미 존재하던 지역 편집 모달의 "연결된 세력" 드롭다운**이 그대로 그 역할을 합니다. 별도 기능을 새로 만들 필요가 없었습니다 — 드롭다운에서 다른 세력을 선택하면 그 즉시 소유권이 이전됩니다(전쟁/조약/행정개편 등 서사적 의미는 사용자가 부여).

## 5. 국가 분리 (영토 일부를 떼어 새 지역 생성)

툴바에 새 도구 "영토 분리"(`mtSplit`)를 추가했습니다. 사용법: 도구를 선택하고, 분리하고 싶은 부분 위에 다각형을 그리면(기존 지역 도구와 같은 자유 그리기 방식), 그린 다각형과 가장 많이 겹치는 기존 지역을 자동으로 찾아 **래스터 기반 폴리곤 차집합(boolean subtraction)** 으로 둘로 나눕니다. 나뉜 결과 중 하나(절단된 부분)는 새 국가 정보 입력 모달(이름·유형·색상, 2장과 동일한 모달)로 이어지고, 확인하면 원본 지역은 잔여 영역으로 줄어들고 새 지역이 추가됩니다.

### 5-1. 알고리즘 — 기존 "빈틈 채우기" 툴킷 재사용

`detectAndFillMapGaps`가 이미 쓰고 있던 래스터화 → 연결요소(flood fill) → 경계 추적(`proceduralTraceComponent`) 파이프라인을 일반화해서 재사용했습니다(`ccComponents` 헬퍼로 연결요소 탐색 부분을 분리).

1. 원본 지역과 사용자가 그린 절단 다각형을 함께 감싸는 바운딩박스를 잡고 격자화합니다.
2. 각 격자 칸이 "원본 지역 안" / "절단 다각형 안"인지 점-다각형 판정(`pointInPolygon`)으로 마스킹합니다.
3. `잔여(remainder) = 원본 AND NOT 절단`, `절단분(carved) = 원본 AND 절단` 두 마스크를 만듭니다.
4. 두 마스크 각각에 대해 연결요소를 구하고, 요소별로 경계를 추적해 다각형으로 만듭니다. **절단선이 지역을 셋 이상의 조각으로 나누는 경우까지 대비**해 모든 연결요소를 다 추적하며, 가장 큰 조각을 "본체"(원본 지역의 남은 영토 / 새 국가의 대표 영토)로 쓰고, 나머지 조각은 확정 시 같은 소속·유형 정보로 복제해서 추가 지역으로 남깁니다 — 그래야 "지도 영역 공백 금지 규칙"을 어기지 않습니다(코드 주석 참고: `mapPerformTerritorySplit`).

### 5-2. 실제로 겪은 버그와 수정

**버그 1 — 부동소수점 STEP으로 인한 경계 추적 조각남.** 처음에는 격자 간격(STEP)을 `(maxX-minX)/220`처럼 실수로 계산했는데, 인접한 두 격자 칸의 경계 좌표가 `offsetX + gx*step + step` 대 `offsetX + (gx+1)*step` 두 가지 방식으로 계산되면서 부동소수점 오차로 미세하게 어긋났습니다(`400.43636363636364` vs `400.43636363636365`). `proceduralTraceComponent`는 좌표 문자열을 키로 삼아 그래프를 만들기 때문에, 이 미세한 차이가 "같은 점"을 "다른 점"으로 오인하게 만들어 경계 루프가 8개 점 만에 끊겨버렸습니다(실제 둘레는 수백 개 점이어야 함). `detectAndFillMapGaps`/`generateProceduralWorldMap`이 원래부터 STEP을 정수로 반올림해 쓰고 있던 이유가 바로 이것이었고, `splitRegionMask`도 동일하게 `Math.round(...)`로 정수 STEP을 쓰도록 고쳤습니다.

**버그 2 — 지형 생성용 단순화 파이프라인이 오목한 모서리를 손상시킴.** STEP을 정수로 고친 뒤에도 절단면이 오목한(reflex) 모서리를 가진 모양(예: 지역 가운데를 네모나게 파낸 모양)에서는 면적이 실제의 1/3 이하로 줄어드는 문제가 남아 있었습니다. 원인을 추적해보니 `proceduralRemoveCollinear` → `proceduralChaikin` → `proceduralDecimate` 조합(원래 절차적 대륙 생성의 매끄러운 해안선을 만들기 위한 용도)이, 격자 경계 추적 자체는 정확한데(원시 루프의 넓이는 정확히 일치) 후처리 단계에서 실제 꼭짓점을 잘못 솎아내 다각형이 자기교차하듯 찌그러뜨렸습니다. 대신 이미 자유 그리기 다각형 단순화에 쓰이던 **`simplifyPoints`(Douglas-Peucker)** 를 재사용하도록 바꿨습니다 — 각 변의 직선성만 보고 점을 솎아내는 방식이라 직각·오목 모서리를 있는 그대로 보존합니다. 이 교체 후 8개 코너를 가진 테스트 도형에서 원시 루프와 완전히 동일한 넓이·좌표가 나오는 것을 확인했습니다.

## 7. 이번엔 범위 밖으로 결정한 것

- 절단 다각형이 여러 기존 지역에 걸쳐 있을 때 한 번에 여러 지역을 동시에 나누는 것 — 현재는 가장 많이 겹치는 지역 하나만 대상으로 삼습니다. 필요해지면 겹치는 지역 목록을 사용자에게 보여주고 고르게 하는 방식으로 확장할 수 있습니다.
- 지역(다각형) 전체를 드래그로 옮기는 기능 — 이전 지도 편집기 업그레이드에서와 마찬가지로 점 객체(마커·게이트·위험구역)만 드래그 대상입니다.
