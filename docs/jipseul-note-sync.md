## ① 지금까지 완성된 최종 코드

### 1-1. 「집필 노트」 앱 구조
- 단일 HTML 파일(약 500KB), 순수 JS(프레임워크 없음), `localStorage`에 데이터 저장.
- 데이터 모델: `WORKS`(작품 폴더) 안에 `DOCS`(설정노트 문서) / `GRAPHS`(관계도) / `MAPS`(지도) / `TABLES`(표) / `TIMELINES`(연표) / `NOVELS`+`MANUSCRIPTS`(원고) / `SPORTS` / `SCRIPTS`(문자, 이번에 새로 추가) 가 매달리는 구조.
- 렌더링 방식: `state.mode`에 따라 `render()`가 분기해서 해당 페이지 렌더 함수를 부르고, 매번 `innerHTML`을 통째로 다시 그리는 방식 (React 등 프레임워크 없음 — 프레임워크 도입 얘기도 나왔으나 "아티팩트는 CDN 스크립트를 못 부르고, 프레임워크 바꾼다고 그림 관련 문제가 해결되는 것도 아님"이라 결론 내리고 안 하기로 함).

### 1-2. 이번 세션에서 새로 추가한 기능들 (전부 완료·테스트됨)
1. **홈 버튼 + 홈 대시보드**: 사이드바 "집필 노트" 글자 클릭 시 홈으로. 홈 화면은 통계(작품 수/총 글자 수 등) + 작품 카드 그리드로 새로 디자인.
2. **오드아이(헤테로크로미아)**: 등장인물 외견 편집에서 "오드아이" 체크 시 왼쪽/오른쪽 눈 색을 따로 지정 가능.
3. **외견 메모 토글**: 항상 펼쳐져 있던 메모칸을 "메모 더보기/접기" 토글로 변경, 체형 선택 칸 바로 아래 위치.
4. **커스텀 색상 선택**: 프리셋 스와치 옆에 무지개색 원(네이티브 `<input type=color>`) 추가로 아무 색이나 고를 수 있음. 고른 색 아래에 `#헥스코드 · 색 계열명`(예: "파랑 계열")이 항상 표시됨 (`colorFamilyName()` 함수, HSL 기반 자체 알고리즘).
5. **맞춤법 검사**: 원고 입력창 3곳(`msText`, `bookEditText`, `bookEditFlow`) 전부 `spellcheck="true"`. 고유명사 오탐은 "우클릭 → 사전에 추가" 안내 문구로 대응(플레인 텍스트칸이라 단어별 예외 처리 자체가 기술적으로 불가능해서 이렇게 처리).
6. **원고 통계 바**: 원고 편집 화면 상단에 "이 화 / 소설 전체 / 화 평균" 글자 수 표시 (`novelStats()`, `updateMsStatsBar()`).
7. **찾아바꾸기**: `msText`, `bookEditText`에 찾기/바꾸기 팝오버 (`openFindReplace()`). 양장본 두쪽(스프레드, contenteditable) 모드는 한글 IME 리스크 때문에 의도적으로 제외.
8. **등장인물 백링크**: 인물 문서에 "등장 화" 카드 표시, 클릭 시 해당 원고로 이동 (`renderCharacterAppearancesCard()`). 문서 열 때마다 전체 화를 다시 스캔해서 놓치는 화 없게 함.
9. **통합 검색**: 검색창 Enter 시 문서+원고+문자를 한 번에 보여주는 결과 페이지, `<mark>` 하이라이트 (`renderSearchPage()`, `collectSearchResults()`).
10. **"문자" 기능 (신규 콘텐츠 타입, `SCRIPTS` 배열)**:
    - 손글씨 문자 그리기: SVG 포인터 드로잉 패드, 실시간 손떨림 보정(EMA 스무딩, alpha=0.4), 여러 획 지원, 카드 클릭으로 재편집.
    - 대응 문자 직접 지정 방식(AI 자동인식 아님 — 사용자가 명시적으로 선택한 방식).
    - 단어/문장 대응표(사랑=love 식 2칸 리스트).
    - **미리 써보기**: 타이핑한 로마자를 손그림 문자로 실시간 변환해 보여줌. 각 글자를 실제 잉크 범위(바운딩박스)만큼만 옆으로 이동시켜서 밀접하되 안 겹치게 배치 (`renderGlyphSequenceSvg`, `glyphBBox`).
    - **한글 자모 자동 분해**: 완성형 한글(가,한,닭 등)을 타이핑하면 유니코드 표준 분해로 초성·중성·종성으로 쪼개서, 낱자 단위로 매핑된 글자가 있으면 자동으로 이어 그림 (`decomposeHangul`, `expandRenderUnits`). 완성형 글자 자체가 매핑돼 있으면 그게 우선.
    - **가상 키보드**: "간단히"(4행) / "텐키리스"(풀 배열: F행+숫자+QWERTY+ASDF+ZXCV+모디파이어+방향키+Ins/Home/PgUp 등) 토글. 물리 키보드 위치(`KeyboardEvent.code`) 기준이라 한/영 전환과 무관하게 눌린 키가 정확히 반짝임. 키 클릭으로도 입력 가능.
    - **글자 표현 방식 2종 지원**: `strokes`(손으로 그린 SVG 획) 또는 `{fontChar, fontFamily}`(내장 폰트의 실제 글자) 둘 중 하나로 표현 가능 (`glyphVisualHtml`, `kbGlyphPreviewHtml`가 분기 처리).
11. **클링온어(pIqaD) · 텅과르 참고표**: 실제 오픈소스 폰트(SIL Open Font License, `dadap/pIqaD-fonts`의 pIqaD qolqoS + `Tosche/Alcarin-Tengwar`) 를 base64로 앱 CSS에 직접 내장(`@font-face`). "장르별 기능 템플릿"(예시 작품) 안에 문자 예시 2개로 들어가 있음 (`createGenreTemplateWork()` 안의 `scriptKlingon`/`scriptTengwar`). 클링온 26자, 텅과르는 자음 20개 + 모음(공용 캐리어 글자) 5개 + 장모음 표시 1개.
    - **주의**: 텅과르는 진짜 문자 체계(모음이 자음 위 부호)가 아니라 이 도구(로마자 1글자=그림 1개) 구조에 맞춘 간소화 버전 — 앱 안에 이 사실이 안내 문구로 이미 들어가 있음.

## ② 현재 직면한 문제점

### 2-1. AI로 생성받은 캐릭터 그림(`output.zip`)이 실제로 못 쓰는 상태
다른 대화창에서 "AI 캐릭터 파이프라인 정리 문서"를 넘겨주고 ComfyUI로 뽑은 결과물인데, 확인해보니:

- **레이어가 분리가 안 됨 (제일 치명적)**: `hair_bob.png`, `top_blouse_bustmedium.png`, `bottom_jeans.png`, `shoes_sneakers.png` 등 매 파일이 "그 항목만" 담긴 투명 레이어가 아니라 **매번 얼굴+머리+상의+하의+신발이 다 같이 있는 완성 캐릭터 통짜 렌더**임. 즉 "부위별로 독립적으로 조합"이 불가능한 상태.
- **얼굴이 그려져 있음**: 이목구비는 코드(SVG)로 계속 그리기로 결정했는데, 모든 이미지에 실제 얼굴이 이미 박혀 있어서 그 결정과 충돌.
- **일부 헤어 그림 자체가 부실함**: `hair_bob.png`는 사실상 빈 캔버스에 잡티 몇 개뿐, `hair_long_straight.png`도 머리카락이 거의 안 보임.
- **화풍 불일치**: 원래 정한 "플랫 라인아트, 굵은 외곽선" 스타일이 아니라 사실적인 3D 렌더(Daz/ZBrush 마네킹 느낌)로 나옴 — 지금 앱의 부드러운 손그림풍과 안 맞을 가능성 높음.
- **정리 안 된 루즈 파일 176장**(`Flux.1_Dev_00001_.png` 등)은 이 프로젝트와 무관한 인물 사진 테스트 결과물 — 쓸 내용 없음.
- (좋은 점도 있었음: 파일명·정리 구조는 제가 드린 ID 체계와 정확히 일치했고, 배경 투명도는 픽셀 단위로 실제로 정확했고, 캔버스 크기(832×1216)·T포즈 프레이밍은 전부 일관됐고, 노출형 상의도 가슴 5단계별로 정확히 나눠 뽑혀 있었음.)

### 2-2. 문제 원인 추정 (미확정)
"이 옷을 입은 사람을 그려줘" 방식으로 매번 완성 캐릭터를 생성했을 뿐, **생성 후 부위별로 마스킹해서 원하는 레이어만 남기고 나머지를 투명 처리하는 후처리 단계가 빠진 것**으로 추정됨. 이 단계에 필요한 도구로 `Cozy Human Parser`(`cozymantis/human-parser-comfyui-node`, SCHP 기반, LIP/ATR 파서로 Hair/Face/Upper-clothes/Pants/Skirt/Shoes 등을 개별 마스크로 분리)를 추천했음.

### 2-3. 확인이 막힌 부분
사용자가 "여러 모델을 받았는데 추출이 잘 안 된다"고 했는데, **정확히 어떤 모델/노드를 받았는지 아직 확인 못함**:
- 집에서 작업한 세션이 **로컬 전용**이라 이 환경의 세션 검색 도구(`mcp__ccd_session_mgmt__*`)로 안 잡힘 (같은 cwd의 세션 3개 확인했지만 관련 내용 없음, "ComfyUI"/"human parser" 키워드 검색도 0건).
- `claude.ai/code` 웹 버전도 확인해봤지만 **스마트폰 앱 세션만 동기화**돼 있고 집 데스크톱 로컬 세션은 안 보임.
- → 사용자가 직접 확인해서 알려줘야 진단 가능한 상태로 남아있음 (아래 "다음 할 일" 참고).

### 2-4. 아직 구현 안 된 것 (알고 있는 채로 보류 중)
- **메시 워프가 실제 앱에 이식 안 됨**: 데모(위 6e233096 아티팩트)에서 코드(`buildMesh`, `warpTriangle`, `widthRatioAtY`)는 이미 검증까지 끝났지만, 진짜 체형 이미지가 없어서 실제 「집필 노트」 앱에는 아직 안 옮김.
- **LayerDiffusion의 FLUX 지원 여부 미확인**: 배경 투명화 관련해서 실제로 FLUX에서 되는지 검색/확인이 필요한 상태로 남아있음.

3. **LayerDiffusion FLUX 지원 여부 확인** — 검색해서 실제로 되는지, 안 되면 대안(rembg/SAM/크로마키) 확정.

   - 가슴 5단계·노출형 의상 컷아웃 합성 로직 구현.

### 작업 방식 메모 (새 세션이 알아야 할 실전 팁)
- 아티팩트 소스를 읽을 땐 `WebFetch(url, "return the complete raw HTML source verbatim")` — 큰 파일은 자동으로 `tool-results/...html` 파일에 저장되니 그걸 읽을 것.
- 받은 원본은 클로드 아티팩트 샌드박스 런타임 껍데기(`<script>window.__FRAME_PREAMBLE=...` 등)가 앞에 붙어있음 — `<title>`이 시작되는 지점부터 끝(`</script>` 마지막)까지만 잘라내서 실제 콘텐츠로 써야 함.
- 재배포할 땐 `Artifact` 도구에 `url` 파라미터로 기존 URL을 넘겨야 링크가 유지됨.
- 큰 base64 문자열(폰트 등) 다루는 작업은 `Edit` 도구보다 Python 스크립트로 문자열 치환하는 게 안전함(이 세션에서 실제로 그렇게 처리함).
